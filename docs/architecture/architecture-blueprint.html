Architecture blueprint

The structure every feature will be built into from now on: modular, scalable, security-first and aligned with SOC 2. It says what exists, what must be rebuilt, and in what order.

1 · Principles

Six rules that decide every later choice.

Modules with contractsEach capability is a module with a published interface. Nothing reaches into another module's tables or files.
Deterministic core, models at the edgeRules compute. Models only interpret, in a fixed form, behind an interface, and a person confirms.
Everything has a sourceEach value records where it came from, which reader and version produced it, and who accepted it.
Untrusted until provenFiles, drawing text and model output are all treated as untrusted and validated at the boundary.
Swappable infrastructureStorage, queue, renderer, OCR, model runtime and sign-in sit behind adapters. One box today, a cluster later, same code.
Evidence by defaultTests, logs and approvals are produced as a side effect of normal work, so an audit is a report, not a project.

4 · Recognition as a pipeline of stages

Today it is one function that grew. It becomes stages with typed inputs and outputs. Each stage's output is stored, versioned and testable alone, so a failure names the stage, and a re-run can start from any point.

Intakesafe? readable? what kind?
Layoutviews, tables, notes, title block, pictures
Readtext layer; OCR for pictures
Scenearrowheads, dimension lines, leaders, scale per view
Calloutsvalues, frames, symbols
Interprettolerance scheme, notes, title block fields
Applylimits by rules
Auditcoverage, mismatches
Stage contractEach stage declares its input type, output type and version. Outputs are immutable and keyed by drawing hash plus stage version.
Named settings, not magic numbersEvery threshold lives in one typed configuration with a description and a test that covers it.
Golden gateA change to any stage must reproduce the golden set, or the expected change must be reviewed and re-approved.
Readers are plug-insA new CAD style, a DXF reader or a new OCR engine is a new adapter, not a change to the pipeline.

8 · Security, in layers

IdentitySingle sign-on through the customer's provider, local accounts with strong password rules when air-gapped, session expiry, optional second factor.
AuthorisationRoles: viewer, inspector, reviewer, administrator. Checked on every route in one place. Every query is scoped to the tenant.
Untrusted filesOpened only in the parse worker: no network, capped memory, time and pages, read-only file system. A hostile file can crash that worker and nothing else.
Untrusted text and modelsDrawing text is data, never instruction. Model output must match a schema and cite text that exists, or it is discarded.
Data protectionEncrypted volumes and connections, keys held outside the code, export-control markings carried on every export.
AuditSign-in, view, edit, accept, export and settings changes are logged with user, time and record. The log is append-only and tamper-evident.
Web hardeningRestricted origins, security headers, input size limits, rate limits, no secrets in the browser.
Supply chainPermissive licences only, pinned dependencies, a bill of materials per release, vulnerability and secret scans as release gates, signed images.
OperationsStructured logs with no drawing content, metrics, alerts, backups, documented restore and incident steps.

9 · SOC 2 alignment

One thing to be precise about: SOC 2 is an audit report on an organisation's controls, issued by an auditor. Software cannot hold it. What we can do is build the product so each control has a feature behind it, and run our own development so the evidence exists. If we ever host this for customers, that hosted service is what gets audited. For an on-site install, customers will ask for the same answers in a security questionnaire.

10 · Engineering rules

Typed and lintedStrict type checking on both sides. A failing check blocks the merge.
Tests at three levelsUnit for rules, contract for adapters, golden and end-to-end for the whole path.
Automated gatesOn every change: tests, golden set, licence check, vulnerability and secret scan, build.
Versioned APIPublished schema, /api/v1, no breaking change without a new version.
Decisions written downA short record for each architectural choice: context, decision, consequence.
Configuration outside codeTyped settings from the environment; the same image runs everywhere.
Errors with meaningOne error catalogue with codes; users see a clear message, logs get the detail.
No stopgap without a labelA temporary choice is marked in code and in the decision record, with the proper version named.
