A small model reads the context. Rules do the arithmetic.

Yes, a small local model is enough, because its job is narrow: understand what the drawing says about tolerances and write that down in a fixed form. It never calculates a limit.

The path of one drawing

recognizerCollect the evidenceNotes, table cells, title block text, with their positions. Already available.
→
small modelInterpretWhich scheme applies, which class, what exceptions. Output is a fixed form, with the text it relied on.
→
checksVerify the answerEvery quoted phrase must exist on the sheet. Standard tables come from our library, never from the model.
→
inspectorConfirm once"ISO 2768 medium, from note 5." One click, saved for the drawing and the customer.
→
rulesApplyRange lookup and limits for every row. Same input, same answer, every time.

What the model is for

  • Naming the scheme: "ISO 2768-mK", "tolerance class medium", "refer company standard"
  • Exceptions in notes: "unless otherwise specified", "dimensions in brackets are reference", "after plating"
  • Scope: "machined surfaces only", different rule for bends, welds or castings
  • Other languages: "Allgemeintoleranzen DIN ISO 2768-m"
  • Notes into requirements: "break sharp edges 0.2 max" becomes an attribute characteristic

What the model must never do

  • Compute a minimum or maximum
  • Decide pass or fail
  • Recall table values from memory
  • Read dimension values off the sheet
  • Change a row without a person confirming

What stays as plain rules

  • Reading a printed tolerance table cell by cell
  • Matching "ISO 2768-m" style names directly, no model needed
  • Looking up the range for each value
  • All arithmetic and the Form 3 text
  • The model is only called when rules do not settle it

The fixed form the model fills in

For the heat sink it would return this. The "evidence" lines are checked against the sheet before anything is shown.

{
  "scheme": "size_range_table",
  "standard": "ISO 2768-1",
  "class": "m",
  "table_on_sheet": true,
  "angular": "from_table",
  "exceptions": [
    { "applies_to": "boxed dimensions", "rule": "basic, no tolerance" },
    { "applies_to": "dimensions in brackets", "rule": "reference" }
  ],
  "needs_customer_profile": false,
  "evidence": [
    "5.UNSPECIFIED TOLERANCE CLASS :- MEDIUM.",
    "m Medium ± 0.1 ± 0.1 ± 0.2 ± 0.3 ± 0.5"
  ],
  "confidence": "high"
}

How small is small

QuestionAnswer
Size of modelA 4 to 8 billion parameter instruction model, quantised. The input is a few hundred words and the output is a short form.
HardwareRuns on a workstation CPU in a few seconds per drawing, faster on a modest GPU. It runs once per drawing, not per row.
Where it runsLocally in the same container stack at the customer. For our own demo data it can run through OpenRouter. Only note and table text is sent, never the drawing.
Title block that is an imageText model alone cannot read it. It needs a small OCR step first, or the customer profile.
Which model exactlyNot decided. Pick by testing two or three candidates on our own drawings and scoring the form they return.
How we know it is rightEach drawing in the golden set gets an expected tolerance scheme. A model or prompt change is scored against it, like the recognizer.
